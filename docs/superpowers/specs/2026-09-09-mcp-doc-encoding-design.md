# MCP 文档库编码治理设计

## 目标

文档库只维护 UTF-8 无 BOM 的 Markdown；任何 MCP 工具对同一文档返回相同的规范文本。

## 设计

`internal/docs` 提供唯一的规范化读取入口。它先在 `MaxReadBytes` 范围内读取完整源文件，再识别 UTF-8、UTF-8 BOM、UTF-16 BOM 或 GB18030，生成规范 UTF-8 文本；分页仅对该文本执行，且页尾不截断 UTF-8 字符。

发生确定性转码时，服务用规范内容回写原 Markdown，并以规范内容计算 revision、建立索引和保存历史。全部写入入口同样规范化 UTF-8 BOM。无法确定的输入不回写、不索引，并返回明确错误。

有效 UTF-8 的既有乱码只在 GB18030 反向转换可严格往返、转换前后可读性评分显著提升时修复；修复前内容进入历史快照。这个条件避免把真实生僻汉字静默改坏。

启动和既有 `docs_rebuild_index` 都执行维护；运行期低频巡检只调用同一重建流程。状态记录扫描、规范化和失败数量。

## 约束

- 不增加 MCP 工具或配置文件。
- 仅处理 `.md`。
- 读取、搜索、章节读取、上下文、历史、索引和编辑路径必须复用规范文本。
- 文件超过 `MaxReadBytes` 不尝试部分转码或索引。
